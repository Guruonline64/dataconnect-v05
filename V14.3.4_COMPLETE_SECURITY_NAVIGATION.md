# DataConnect V14.3.4 — Consistency Fix

This version is a corrective integration release based on V14.3.3.

## Fixed
- Functional in-app back stack for screen navigation.
- Android hardware back delegates to the web app route stack.
- Transaction PIN is visible under Account > Security.
- Transaction PIN is exactly 4 digits.
- Dedicated Transaction PIN management screen: set/change/disable.
- Data purchase is blocked until Transaction PIN is successfully verified.
- Airtime submission is blocked until Transaction PIN is successfully verified.
- Share purchase is blocked until Transaction PIN is successfully verified.
- Shareholder withdrawal request is blocked until Transaction PIN is successfully verified.
- PIN is sent to the backend authorization endpoints and the backend verifies a hashed PIN.
- Backend locks PIN verification for 15 minutes after 5 failed attempts.
- Backend migration creates one transaction PIN record per user.
- V2 compatibility routes were added for the frontend's purchase/PIN endpoints.

## Validation
- JavaScript syntax checked with Node.
- Laravel PHP controller, migration and route files passed PHP syntax checks.
- Android Gradle was not executed in this environment because the distributed source does not include a Gradle wrapper (`gradlew`). Build in GitHub Actions as usual.
